## Repeat problems

### 1. The "Generated by Claude Code" footer in pull request bodies

- Evidence: merged with the footer as the body's last line: Framework #196, Editors #93, Examples #64, Site #47,
  Private #10 (the five "remove the agent workflow material" pull requests). The setup pull requests' cycle 2 review,
  finding 9: a body edit put the footer back on every body. The Owner's local session has stripped it by hand each
  time.
- Why it got through: the `commit-authors` check, which fails on that footer, was removed by those same pull requests,
  so it did not run on them, and nothing has run since.
- Becomes: a check. Restore `commit-authors` in the four repos with CI, and add "the description ends with
  `Requested by **McThayDT**`".

### 2. Commits as `Claude`, or with a Claude credit

- Evidence: 25 failed `commit-authors` runs on 2026-11-16 before its removal (Framework 11, Editors 8, Examples 4, Site
  2). Every commit on the five `main` branches since 17:00 UTC is McThayDT's, so none slipped through yet, but nothing
  would catch one now.
- Becomes: the same restored check.

### 3. Audits find acceptance criteria with no test

- Evidence: Editors #95 cycle 1, R4 (no journey presses the touch control on a phone) and R5 (the "door into a deleted
  level" case has no test); Editors #96 cycle 1, R3 (several Task 30 bullets have no browser test), R4 (the journey
  skips "push it back, undo") and R5 (the pad test does not check what its name says).
- A program cannot tell whether a test covers a criterion. Becomes: a rule in `review`, the pull request maps each
  criterion to its test, or says "no test" and why, before the audit.

### 4. Journeys that fail once in WebKit or Firefox

  test that delays the fonts); Editors `world-play.browser.test.ts` in WebKit at `52145af` (fixed in #95 with a longer
  readiness wait); Editors `approve.journey.test.ts` in WebKit, run 43928020067 at `83c7274` (the setup drag did not

- Becomes: one lesson in Editors' and Site's `history.md` (fonts). The approve drag stays an open item in Editors'
  `progress.md`: one failure is a defect to report, and its cause is still a guess.
