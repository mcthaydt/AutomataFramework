## Important

**I1. The README does not show how to get a player's language, so its examples no longer run.** Plan W makes
`startGame` and `startOnlineGame` refuse to start until `locale.asked()`, and makes `onlineWords` need its words. Task 10
Step 4 asked the README's `createLocale` example to show `locale.language()` being `undefined`, `languagePicker` and
`set`. On `d00a135`:

- `languagePicker` is not named anywhere in `README.md`. The first example (`startGame({ content, locale, … })`, line
  97) uses a `locale` the page never makes, and nothing shows the picker that has to come before it. A first-time
  developer following the README cannot get to a running page, which the onboarding rule forbids.
- The `startOnlineGame` example (line ~383) passes no `locale` (now a required option, and the game throws without
  one) and calls `onlineWords(status)` with one argument (now a type error). The sentence under it still says
  "`onlineWords(status)` is the plain English for the room", which is the default the spec removes.
- The content rules (line 778) still say "A game's words live in `messages` files, one per language, and English
  (`en.json`) comes first." The plan gave the new sentence: "…and `source` in `automata.toml` names the one the team
  writes in".

**Fix (stage 6):** in "Languages", show the whole first visit: `createLocale`, then
`if (!locale.asked()) await languagePicker({ mount, locale }).done`, then `startGame`, and point the first example at
it; give the `startOnlineGame` example `locale` and `onlineWords(status, locale.words)`, and drop "plain English";
replace the line 778 rule. Add the three to `tests/docs/readme.test.ts` (it already holds
`onlineWords(status, locale.words)`, which is why the later paragraph is right and the example is not).

**I2. PR 94's description carries a Claude credit, and the `commit-authors` check lets it through.** PR 94's body ends
with `_Generated by [Claude Code](https://claude.ai/code/session_…)_`, which the Owner's rule forbids ("no 'Generated
with Claude Code' in … pull request bodies"). `scripts/check-commit-authors.ts` only matches
`generated with [claude code`, so the "by" form passed (`commit-authors` is green on `d00a135`). The commits themselves
are clean: all 39 are authored and committed by McThayDT, and no message names Claude. **Done during this audit:** the
line is taken out of PR 94's description. **Fix (stage 6):** widen the pattern to `generated (with|by) \[?claude code`
and add the "by" form to the script's test, so the next one fails CI.

## Minor

**M1. Three comments still say English where the code no longer does.** `src/features/net/protocol.ts:52`
("`onlineWords` says each in English"), `src/features/content/read-marks.ts:125` ("from the English text") and the
parameter name `readMark(english, translated)` there (the plan's interface names it `sourceText`). Comments are out of
the `no-default-language` rule's reach on purpose, so only an audit finds these.

**M2. The flags jump when the first one is chosen.** With none chosen the globe (56 pixels) stands above the flags;
choosing one swaps it for the title, which is shorter, and the whole group moves up about 15 pixels
(`pr-94/chromium/picker-phone-390x844.png` against `picker-chosen-phone-390x844.png`). On a phone the flag a player
just tapped moves under their finger. Give the globe and the title one box of the same height.

**M3. `create`'s stop sentence always says `my-game`.** With no `--source` and no device language it answers
`…like automata create my-game --source es.` whatever name was typed. Use the name given, so the line can be copied
as it is.

**M4. The new game's `index.html` does not say why it has no `lang`.** The template's `biome.template.json` turns
`useHtmlLang` off for it, and only the framework's own `CLAUDE.md` says why. A game's developer (or agent) who meets
a page with no `lang` has nothing to read. One HTML comment beside the icon's ("No `lang`: the page sets it once the
player has picked a language") does it.

**M5. The rule does not see English by its full tag.** `ENGLISH_BY_NAME` catches `'en'`, `.en` and `en-GB`, but not
`'en-US'`, so `navigator.language ?? 'en-US'` would pass. Add `\ben-US\b` and allow the one `LANGUAGE_TAGS` line in
`src/features/locale/names.ts`, the same way the two lines it allows today are allowed.

**M6. The tracker still counts 135 words before Release 1 in two places.** Task 10 Step 5 said the "Before Release 1"
line changes to 145 (29 words in each of five languages). The Cycle 5 log says 145 and calls the 135 lines history,
but the plan L execution row and the plan L log line under it still read 135 as today's number. Fixed in this pull
request's `progress.md`.
