# M2 Plan S: Audio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, in
> one session, with no subagents (project rule). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A game plays the sounds and the music its `sound`, `music` and `cues` files describe, made at run time from
numbers, when the sim's events say so; the player sets two volumes; and nothing a speaker does can ever reach the sim.

**Architecture:** A new headless feature, `audio`, reads the game's cue lists and turns each sim event into "play this
sound" or "start this track". It keeps a cue log of what it asked for and when, and plays through a small port it
owns, the `Speaker`. It is handed a step's events and never the sim, so it has nothing to change. The page's speaker
(`webSpeaker`, Web Audio, in the `web` feature) builds each voice from oscillators and seeded noise, starts on the
first tap or key, and sleeps while the game is off screen; a `testSpeaker` runs the whole feature in Node. The three
audio kinds of content are left out of what the sim hashes, so changing a sound cannot move a hash either.

**Tech Stack:** TypeScript 7.0.2 strict, Zod 4.6.6, the browser's own Web Audio API, Vitest 5.0.3 (browser mode on
Playwright 1.63.0), Biome 2.5.15, knip 6.39.0, pnpm 10.34.6, Node 24.21.0. No new dependency.

**Spec:** [`docs/superpowers/specs/2026-11-14-m2-design.md`](../specs/2026-11-14-m2-design.md), the section "Audio
(plan S)", the `sound`, `music` and `cues` row of "Content: the new files", and the Testing line "Sound is tested by
what plays when (the cue log), not by listening"; on top of
[`2026-11-13-2d-first-layer-design.md`](../specs/2026-11-13-2d-first-layer-design.md). Principles served: 1 (a sound is
numbers in a documented file, and the cue log and `testSpeaker` let an agent check what plays with no page and no
ears), 2 (the two volumes and the "Tap to start the sound" button are touch first), 3 (2D only), 4 (one package),
6 (the old stack, nothing added), 7 (the old synth's voice, its unlock and its limits are ported for this layer only).

## What this plan covers, and what it does not

Covered: the `audio` feature (cues, the cue log, sounds, the music player, two volumes), the `Speaker` port with its
test and web forms, the "Tap to start the sound" button, `startGame` giving a game's events to its audio, the proof
that audio moves no hash, and journeys in three real browsers.

Not in this plan, each with its reason:

- **The file formats.** `sound`, `music` and `cues` are plan C's and are on `main`. This plan changes none of them.
- **The settings screen and its words.** The two sliders, and the sentences for "the sound has not started" and "this
  device has no sound" in six languages, are plans U and L. This plan exports the settings' shape and first values,
  and the state those screens show (see "What the other plans rely on"). It ships one English sentence of its own,
  on the button a game gets before it has screens.
- **Which events a game raises.** `hero.jumped` is the game's own plugin's event (`defineEvent`, `ctx.emit`);
  `spark.taken` and `door.touched` are plan P's. Audio answers any event by its name and defines none in the sim.
- **`feel` files** (dust, shake, freeze). They answer events the same way but draw and hold the picture, so they
  belong to the plan that builds the feel runtime, not here.
- **Sound in watch mode.** The spec says watching stays silent. `watchReplay` takes no audio and is not changed.
- **Sounds that come from a place** (panning, quieter when far), ducking, and recorded audio files. Left out because
  nothing in M2 uses them: the showcase is one screen wide per level and has five sounds and one track. The `Speaker`
  port plays a voice on a bus, so each can be added later without changing a content file.
- **The demo using sound.** That is plan D's step for S, in AutomataFrameworkExamples, after this plan has merged
  and the pin has moved.
- **A changeset.** Nothing is published per plan (the Owner, 2026-11-13).

## Global Constraints

- **Audio never changes the sim.** Nothing in `sim`, `physics`, `commands`, `content` or `level` imports `audio`.
  `audio` is never given a `Sim`: it is given `{ tick, events }` from a step that has already happened, and reads
  only each event's `type`.
- **No recorded hash moves.** `tests/golden/push-crate.json`, `co-op.json`, `physics-scene.json` and `bounce.json`
  are not changed by any task. A golden that moves is a stop.
- The sim has no I/O, no wall clock and no `Math.random`. `audio` keeps to the same rule though it is not a pure
  feature: its only clock is the speaker's (`speaker.now()`), so a test moves time by hand.
- `audio` touches no page API. `AudioContext`, `OfflineAudioContext`, the page's taps and keys, and the button are
  named only under `src/features/web/`. Both rules are held by the architecture check, not by care (audit M8):
  Task 2 adds `'audio'` to `PURE_FEATURES` in `tests/architecture/rules.ts`, so a clock, a timer, `Math.random`,
  `fetch` or a `node:` import in `src/features/audio/` is refused as it is in the sim.
- A sound that cannot play is an answer, never a throw into the game's loop and never silence nobody is told about:
  `state()` says `waiting` or `unavailable`, and the cue log still says what was asked for.
- Effect is never imported under `src/`. Zod is the only schema language.
- A source file has at most 600 lines. Features import only features below them, through the entry file.
- Comments say why. Every exported name has a doc comment (the API report prints them).
- **Nothing is run locally**: no test, and no `pnpm` command either (the coordinator, 2026-11-14). Every check is a
  pull request's CI run, read with `gh run list --branch <branch>` and `gh run view <id> --log-failed`.
- No Claude attribution anywhere; commits are by `McThayDT <107786093+mcthaydt@users.noreply.github.com>`, set before
  every commit and held by a local hook that refuses any other author.
- Words a person reads (the button, the README) pass the drunk-grandma test.

// ---- audio (headless): src/features/audio/audio.ts ----

/** Where a voice plays: sound effects or the music. Each has its own volume. */
export type Bus = 'sound' | 'music'

/** 'waiting': nothing can be heard until the player taps or presses a key. 'unavailable': this device has no sound. */
export type SpeakerState = 'waiting' | 'on' | 'unavailable'

/** What audio plays through. Every way of making sound is one of these; nothing else makes a noise. */
export interface Speaker {
  state(): SpeakerState
  /** Called on every change of state. Returns a function that stops listening. */
  onState(listener: (state: SpeakerState) => void): () => void
  /** Seconds on the speaker's own clock. It stands still while the state is not 'on' and while the speaker sleeps. */
  now(): number
  /** Called several times a second while the speaker is on and awake, so music can be handed over a little ahead. */
  onClock(listener: () => void): () => void
  /** Plays one voice on a bus. `voice.at` counts from `when` (speaker seconds). Does nothing unless the state is 'on'. */
  play(bus: Bus, voice: SoundVoice, when: number): void
  /** A bus's volume as the player set it, 0 to 1. Kept while waiting, so it is right when sound starts. */
  volume(bus: Bus, value: number): void
  /** Fades out everything on a bus, voices handed over for later included. */
  cut(bus: Bus): void
  /** Lets go of everything. Safe to call twice. */
  close(): void
}

/** One voice a speaker was given, as the test speaker remembers it. */
export interface PlayedVoice { readonly bus: Bus; readonly voice: SoundVoice; readonly when: number }
/** A speaker that makes no sound and remembers everything, for Node and for tests. */
export interface TestSpeaker extends Speaker {
  /** The first tap: 'waiting' becomes 'on'. Nothing happens when unavailable. */
  tap(): void
  /** 'on' becomes 'waiting', as when a phone call takes the sound away. */
  interrupt(): void
  /** Moves the clock on (only while 'on'), then calls the clock listeners once. */
  advance(seconds: number): void
  readonly played: readonly PlayedVoice[]
  /** Every `cut`, in order. */
  readonly cuts: readonly Bus[]
  /** The last volume given for each bus; 1 until told. */
  readonly levels: Readonly<Record<Bus, number>>
  readonly closed: boolean
}
export function testSpeaker(options?: { readonly state?: SpeakerState }): TestSpeaker   // default 'waiting'

/** The player's two volumes, 0 (silent) to 1 (full). The `sound` section of the settings. */
export interface SoundSettings { readonly format: 1; readonly music: number; readonly sound: number }
export const SoundSettingsSchema: z.ZodType<SoundSettings, SoundSettings>
export const SOUND_SETTINGS_DEFAULT: SoundSettings        // { format: 1, music: 0.7, sound: 1 }, frozen

/** One thing a cue asked for. `skipped` is there only when it was not played. */
export interface CueLogEntry {
  /** The tick of the step it was heard in; for a page event, the last tick heard. */
  readonly tick: number
  /** 'sim': an event from a step. 'page': an event raised outside the sim (a level starting, a menu). */
  readonly from: 'sim' | 'page'
  readonly on: string
  readonly do: 'sound' | 'music' | 'stop-music'
  /** The sound's or track's id; left out for 'stop-music'. */
  readonly id?: string
  /** 'busy': too many sounds were already playing (see the limits). */
  readonly skipped?: 'busy'
}

/** At most this many of one sound at once, and this many sounds in all. Counted in ticks, so it is the same everywhere. */
export const MAX_SAME = 4
export const MAX_SOUNDS = 16
/** The cue log keeps the newest this many entries. */
export const LOG_MAX = 1024

export interface GameAudio {
  /** True when the game has no cue at all: there is nothing to play and nothing to tell the player. */
  readonly silent: boolean
  /** A new sim is about to be heard: forgets the last tick and which sounds are still playing. Music carries on. */
  begin(): void
  /** Answers one step's events. A step whose tick was already heard is ignored. */
  hear(result: { readonly tick: number; readonly events: readonly SimEvent[] }): void
  /** Answers an event from outside the sim, by name. A name no cue answers does nothing. */
  raise(event: string): void
  /** What the cues asked for, oldest first. A copy. */
  log(): readonly CueLogEntry[]
  /** The track wanted now, playing or waiting for the first tap; `undefined` for none. */
  music(): string | undefined
  volumes(): SoundSettings
  /** Throws a `RangeError` in plain words for a volume that is not a number from 0 to 1. */
  setVolumes(volumes: SoundSettings): void
  /** A short tone on one bus, so a player hears the volume they just set. Not a cue, so not in the log. */
  sample(bus: Bus): void
  state(): SpeakerState
  onState(listener: (state: SpeakerState) => void): () => void
  /** Stops the music and fades every sound. Cues go on being answered. */
  stop(): void
  /** `stop`, and stops listening to the speaker. The speaker is closed by whoever made it. Safe to call twice. */
  close(): void
}
/** Throws an `Error` in plain words when a cue names a sound or a track the content does not have. */
export function createAudio(options: {
  readonly content: GameContent
  readonly speaker: Speaker
  /** Ticks a second, for counting how long a sound lasts. Default 60. */
  readonly tickHz?: number
}): GameAudio

/** A note's pitch in hertz: `hertzOf('A4')` is 440. `undefined` for anything that is not a note. */
export function hertzOf(note: string): number | undefined
/** One note of a track, timed. */
export interface ScoreNote {
  readonly part: string
  /** Seconds from the track's start. */
  readonly at: number
  /** What a speaker plays: `at` is 0 and `volume` is the part's times the track's. */
  readonly voice: SoundVoice
}
/** A track as timed notes, in the order they start. */
export interface Score { readonly id: string; readonly seconds: number; readonly loop: boolean; readonly notes: readonly ScoreNote[] }
export function scoreOf(music: MusicFile): Score

export function simContent(content: GameContent): GameContent

export interface SpeakerSeams {

  /** Where taps and keys land. Default `window`. */

}

export function webSpeaker(options?: { readonly host?: Host; readonly seams?: Partial<SpeakerSeams> }): Speaker

Facts the other plans may rely on:

- **A cue answers an event by its name alone**, whatever its payload. Every cue for an event runs, files in id order
  and cues in file order. All its sound cues play; of several music changes for one event, the last is the one that
  counts.
- **Page events.** `startGame` raises `level.started` once, when the level is on screen. Any other name is the
  game's or a screen's to raise with `audio.raise(name)` and to answer in a cue list; this plan defines no other.
- **Sounds are never played late.** A sound asked for while the state is not `on` is logged and not played. Music is
  the other way round: the track wanted when the first tap comes starts then, from its beginning.
- **A track already wanted is not started again.** `level.started` in level two leaves level one's track playing if
  both name the same one. So one `GameAudio` is made per game, not per level.
- **The limits.** In one tick a sound starts at most once; at most `MAX_SAME` of one sound and `MAX_SOUNDS` sounds
  are playing at once, a sound lasting `ceil(seconds * tickHz)` ticks from the tick it started. One over a limit is
  logged with `skipped: 'busy'` and not played. Page events are not limited: a person paces them.
- **What the limits count** (audit I5). Only sounds from sim events: a page event's sound is never counted, so a
  menu pressed at any moment cannot change which sim sound is `busy`. A sim sound asked for while the state is not
  `on` is counted as playing all the same, so the log does not depend on when the player tapped.
- **A page event's tick** is the last tick heard since `begin()`, and `0` when none has been (a fresh `GameAudio`, or
  `level.started` straight after `begin()`).
- **The cue log is the same in every engine** for the same events, because nothing in it comes from a clock or from
  whether the speaker was on.
- **Stored form.** The settings section is `sound`: `{"format":1,"music":0.7,"sound":1}`.
- **A setting is turned into loudness by the speaker**: the web speaker's gain is the setting squared, so half way
  along a slider sounds about half as loud.
- **Audio files are not in the sim's content.** `createGameSim` gives the sim `simContent(content)`. Changing a
  sound, a track or a cue list does not change `contentHash`, any snapshot or any replay's hashes, and
  `verifyReplay` does not answer `content-changed` for it.
- **Plan U** makes the settings section and wires it, three lines:
  `const sound = settings.section({ name: 'sound', schema: SoundSettingsSchema, initial: SOUND_SETTINGS_DEFAULT })`,
  `audio.setVolumes(sound.get())`, `sound.onChange(audio.setVolumes)`. A slider calls `audio.sample(bus)` when it is
  let go. Its screens show `audio.state()` in plain words in six languages (`waiting`, `unavailable`), pass
  `soundNotice: false` once they do, and raise their own page events for menu sounds. Watch mode stays silent:
  `watchReplay` has no audio.
- **Plan N.** `hear` ignores a tick it has already heard, so the steps a rollback runs again make no second sound. A
  sound from a guess the server then corrects is not taken back. `hear` takes one step at a time (audit I3): an
  online game calls it once for each step `predicted` runs for the first time, with that step's own tick and events,
  never once for a whole `advance` (whose `events` today run several ticks together, which would join their sounds
  into one tick and log them on the wrong one). `startOnlineGame` takes `audio` and `soundNotice` as `startGame`
  does, raises `level.started` once the level is on screen, and calls `audio.begin()` after a `sync` restores the
  sims, since the tick after a sync need not follow the last one heard. Task 9 builds this if `startOnlineGame` is
  on `main` by then; otherwise plan N's execution does, from this paragraph. Either way plan N's `Advance` gives the
  fresh steps one by one, `steps: readonly { tick: number; events: readonly SimEvent[] }[]`, in place of or beside
  its `events`.
- **Changing a sound does not stop two players sharing a room.** Plan N's version check compares `contentHash`,
  which no longer holds the audio files: two players whose sound files differ play together, each hearing their own.
  That is right, since the sims are the same.
- **Plan K.** The template from `automata create` makes one `GameAudio` and one `webSpeaker` and passes them to
  `startGame`. `automata check` can say when a cue names an event no plugin defines: the sim lists its events'
  ids. A running game's state, for `automata mcp`, can carry `audio.log()` and `audio.state()`.
- **Plan D's step for S** (Examples): the hero's plugin emits `hero.jumped` and `hero.landed`; the demo gains its
  sound, music and cue files; its journey taps, sees the button go, and reads the jump in the cue log. Adding
  events to the demo's plugin changes that sim's schema, which its goldens carry: that step records them again in
  CI and shows the Owner before and after, as the spec's "Goldens" says.

### Task 3: Notes and the score

**Files:**

**Interfaces:**

- Produces: `hertzOf`, `ScoreNote`, `Score`, `scoreOf` (the contract above).

`hertzOf` uses a table, not `Math.pow`, so a pitch is the same number in every engine: the twelve notes of octave 4
below, times two for each octave up and halved for each octave down (both exact).

| C | C# | D | D# | E | F | F# | G | G# | A | A# | B |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 261.6256 | 277.1826 | 293.6648 | 311.127 | 329.6276 | 349.2282 | 369.9944 | 391.9954 | 415.3047 | 440 | 466.1638 | 493.8833 |

A flat is the note a step below (`Db4` is `C#4`); `Cb4` is `B3` and `B#4` is `C5`. Every step the music schema
accepts as a note (`[A-G][#b]?[0-8]`) has a pitch, the two that leave the octaves 0 to 8 included: `B#8` is C9's
8372.0176 and `Cb0` is B-1's 30.8677 (audit M3). `C9` itself is not a note, as the schema says.

`scoreOf`: one step lasts `60 / (tempo * stepsPerBeat)` seconds. A tone step is a note of that length, and each `=`
after it makes it one step longer; `-` is a rest; `=` with no note before it in the part is a rest (a hold never
wraps round from the end of the track), and so is `=` after a rest: it holds the rest (audit M4). A hold carries
on across the end of a row, since a part's rows joined are its steps. A tone note's voice is
`{ kind: 'tone', wave: <the part's>, from: hertz, to: hertz, at: 0, length, volume: part.volume * music.volume }`.
A drum hit `x` is `{ kind: 'noise', pitch: 150, at: 0, length: 0.1, volume: part.volume * music.volume }`, whatever
the step's length. `seconds` is the step count times the step length. Notes are in the order they start; notes
that start together are in the parts' order.

`playVoice` is the old synth's voice, with these values:

- The voice starts at `t = when + voice.at`. Its gain is set to `voice.volume` at `t` and falls with
  `exponentialRampToValueAtTime(0.0001, t + voice.length)`.
- A tone is an `OscillatorNode` of the voice's `wave`, its frequency set to `from` at `t` and ramped (exponential) to
  `to` at `t + length`; it stops at `t + length + 0.05`.
- A noise is a looping `AudioBufferSourceNode` over one second of seeded noise (Park-Miller, seed 7:
  `seed = (seed * 16807) % 2147483647`, sample `seed / 1073741823.5 - 1`), made once per context and kept, through a
  `bandpass` `BiquadFilterNode` at `pitch` with `Q` 1; it stops at `t + length`.

`webSpeaker`, with its numbers pinned:

- Nothing is built before the first gesture: `pointerdown`, `pointerup`, `keydown` or `touchend` on `seams.target`,
  listened for in the capture phase. On one, it calls `seams.context()` (default `() => new AudioContext()`) and
  `resume()`. If there is no `AudioContext`, or making one throws, the state is `unavailable` for good and the
  listeners are removed.
- The state is `on` while the context's own state is `running`, and `waiting` otherwise (a browser that suspends it,
  an iPhone's `interrupted`). While `waiting`, every gesture calls `resume()` again. The context's `statechange`
  event is what moves the state.
- The graph: each bus is a gain (the player's volume, squared) into one master gain of `0.5` (room for several
  voices at once) into the destination. `volume()` before the context exists is kept and applied when it is built.
- `cut(bus)` ramps that bus's current inner gain to 0 over `0.3` seconds and gives the bus a new inner gain, so
  voices handed over earlier fade with the old one and new voices are heard.
- With a `host`: when the host says the game is not on screen it calls `suspend()`, and `resume()` when it is back.
  Asleep, the state it reports stays as it was, so no button appears on a hidden page; if the context is not
  `running` once it is back, the state is `waiting`.
- `onClock` listeners are called every `50` ms through `seams.every` while the state is `on` and the speaker is
  awake. `now()` is the context's `currentTime`, and 0 before there is one.
- `close()` removes every listener, stops the clock and closes the context.
