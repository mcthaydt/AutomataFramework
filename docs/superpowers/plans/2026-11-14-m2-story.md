# M2 Plan T: story Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, in
> one session, with no subagents (project rule). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A game's conversations, behaviour rules and cutscenes run: a critter wanders and runs from the hero, a
keeper talks when the hero walks up and offers a choice, and a cutscene moves the camera and its actors, all of it
in the sim, on one hash in Node, Chromium, WebKit and Firefox, and shown to the player in a box of plain words.

**Architecture:** The part that decides is in the `level` feature, beside the other things `createGameSim` switches
on from a game's content: a `Mind` component and a behaviour system, and a `Story` resource stepped by three
commands (`story.next`, `story.choose`, `story.skip`). The part that shows is a new page feature, `story`: a speech
box over the game and the cutscene's camera, which read the sim's state after every tick and decide nothing. A game
with no behaviour, conversation or cutscene has exactly the sim it has today.

**Tech Stack:** TypeScript 7.0.2 strict, Koota 0.6.6, Zod 4.6.6, PixiJS 8.22.0, Vitest 5.0.3 (browser mode on
Playwright 1.63.0), Biome 2.5.15, knip 6.39.0, pnpm 10.34.6, Node 24.21.0. No new dependency.

**Spec:** [`docs/superpowers/specs/2026-11-14-m2-design.md`](../specs/2026-11-14-m2-design.md), "Story (plan T)",
the showcase table's Story and Behaviour rules rows, and the journey "a player meets the keeper, picks a choice and
sees the cutscene"; on top of [`2026-11-13-2d-first-layer-design.md`](../specs/2026-11-13-2d-first-layer-design.md),
layer 11. Principles served: 1 (who talks, what they say, what a critter does and where the camera goes are lines
in JSON files an agent can write, checked with plain sentences; every move a player makes in a story is a recorded
command), 2 (one conversation, one behaviour and one cutscene per file, each node, rule and key a thing a finger
can pick in the M3 Story and Characters editors), 3 (2D only), 6 (the deterministic sim, with parity in four
engines; nothing is added to the stack), 7 (the old repo's `narrative`, `cutscenes` and `interact` are read for
their rules, see "Old code").

## My calls (the builder's, inside the spec)

None needs the Owner. The plan audit may challenge any of them.

1. **What decides is in `level`; what shows is in `story`.** The spec says story runs in the sim, and the layer
   order puts `story` above `render`, `input` and `locale`. Both hold: the sim's part must be in the sim every
   caller of `createGameSim` gets (a page, a replay check, plan N's room server, which sits below `story`), so it
   lives in `level`, where plan I's `join`, plan P's `touch` and plan A's `Sprite` already live for the same reason.
   The `story` feature is the page's part: it needs the renderer's camera, the input's menu presses and the words.
   The other way, a pure `story` feature whose plugins every caller must remember to pass, would let a room server
   and a page run different sims.
2. **Switched on by content, never for everyone.** The sim's schema hash covers every component, command, event,
   resource and system. `behaviourPlugin` joins a sim only when a character has a `behaviour`; `storyPlugin` only
   when the project lists a conversation or a cutscene. The M1 fixture game and Examples' game have neither.
3. **A conversation opens when a hero walks up.** No button to find, so a first-time player cannot miss the keeper,
   and the touch layout keeps its three buttons. It opens once per visit: the hero must walk away and come back to
   hear it again. A game that wants a button calls `startConversation` from its own system; a `talk` field on the
   character is one optional field later.
4. **Only the talker stands still in a conversation; everybody does in a cutscene.** The sim holds a player's hands
   itself (it blanks what they hold, and gives back what is still held when it ends), so a game's own hero code
   needs no change and cannot forget.
5. **Lines wait for the player; a cutscene keeps its own time.** Next, a choice and Skip are commands with the
   player's number, so a replay has them and a rollback replays them.
6. **A skipped cutscene ends where it would have ended:** every actor is put where its last key says. What the
   story changed is the same whether or not the player watched.
7. **The camera's place is not sim state.** It is worked out from the cutscene's file and how long it has played,
   which is sim state. Nothing in the sim reads the camera, so it need not be in the hash.
8. **`blocked` and `on-ground` are read from how the body moved,** not from a ray: `blocked` when it asked to walk
   last tick and physics left it under a tenth of that speed; `on-ground` when it has hardly moved up or down for
   two ticks. No new physics call, and both are plain arithmetic on sim state.
9. **A character's shown name is a message key on the character** (`name`), not a naming habit the box guesses.
10. **A story fixture of its own.** The full fixture game is the one every plan grows (plan A's audit, I4), so this
    plan's goldens are recorded on `tests/fixtures/story/`, which only a change to how a story plays can move.

**Old code** (AutomataFrameworkFailed at `ed8592e8f81db71f114275e2d625a6d7a4a4f22c`, read, not lifted):
`extensions/narrative/src/shared/sim/narrative.system.ts` and `dialogue.ts` (a conversation moves only on a
command; an advance while a choice waits does nothing; the place is a node and a line);
`extensions/cutscenes/src/shared/sim/cutscene.system.ts` (a cutscene is sim ticks: it starts at tick T, ends at

## Global Constraints

- Plan C's Global Constraints hold, word for word: Zod only; `z.strictObject`; every field has a `.describe()`;

  `loadGame`; `writeContent` is the only writer of content; sorting by UTF-16 code unit.
- **No golden in `tests/golden/` moves, and `tests/fixtures/game/` is not changed.** Every new field is optional
  with no default and is the last key of its object, so a file written before this plan is written the same after.
  `Mind`, `Story` and the three commands are in `behaviourPlugin` and `storyPlugin`, never in `levelPlugin`,
  `commandsPlugin` or `joinPlugin`, and no existing plugin's `config` gains a key (configs are hashed). New goldens

  unit and has no repeats. Entities are walked lowest sid first; players lowest number first; commands by `source`

**The order of work in a tick** (a contract; each step lowest sid, lowest player or lowest `source` then `seq`
first):

1. `input`: `level.join` (plan I), then `commands.controls`, then **`level.story.hold`**:
   1. On tick 0, the cutscene of this level with `opens`, if it is not in `seen`, starts.
   2. A cutscene whose time is up ends.
   3. A `story.skip` from a player with a hero ends the cutscene, skipped.
   4. A conversation whose talker's hero or whose thing is gone ends, unfinished.
   5. The talker's `story.choose` and `story.next` commands, merged and in order, each move the conversation once.
   6. Hands: every player in a cutscene, or the talker in a conversation, is held; anyone else held before is let
      go.
2. `prePhysics`: **`level.story.stage`** puts each actor of the playing cutscene where `actorsAt` says.
3. `physics`, `postPhysics`: as today.
4. `gameplay`: **`level.behaviour`**, and **`level.story.meet`** (who is within reach, and whether a conversation
   opens). The game's own systems are in this phase too, ordered by name as today.

**A cutscene ends** (in time or skipped) the same way: every actor is put where `actorsAt(file, file.length)`
says, its id joins `seen`, `scene` is null, `cutscene.ended` is emitted. **A conversation ends** by setting `talk`
to null and emitting `conversation.ended`; when it finished on a node (not cut short) that node is written to

`firstRule`: the first rule every one of whose senses holds. `near` holds when that kind's nearest is closer than

| `follow` | `speed` toward the nearest `to`; 0 when there is none or it is within 0.05 tiles sideways | left alone | `dir` becomes the way it walks |
| `jump` | left alone | `-speed` when on the ground, else left alone | unchanged |

```ts
export interface BoxState {
  readonly speaker?: string            // the name, already in words
  readonly text: string
  readonly choices: readonly string[]  // already in words; when not empty the player must pick
  readonly next: boolean               // show the Next button
  readonly skip: boolean               // show the Skip button
}
export interface StoryBox {
  /** `undefined` hides the box and gives the focus back to whatever had it. */
  show(state: BoxState | undefined): void
  /** Moves the focus to the next (1) or the one before (-1) of the buttons showing; it stops at the ends. */
  move(by: 1 | -1): void
  /** Presses the button that has the focus. */
  press(): void
  setInset(px: number): void
  setHeld(on: boolean): void
  destroy(): void
}
export function createBox(mount: HTMLElement, on: { next(): void; choose(choice: number): void; skip(): void },
  words: BoxWords, options?: { readonly watching?: boolean }): StoryBox
```

The box is one `div.automata-story` inside the mount, hidden when there is nothing to say, with `data-story`
parts: `speaker`, `text` (`aria-live="polite"`), `choices` (one `<button data-choice="0">` each), `next`, `skip`.
It sits `12px` from the mount's left and right edges (at most 640 px wide, centred), its bottom `12px` above the
touch buttons' inset, at most 40% of the mount's height; the text scrolls inside it and the buttons never scroll
away. When choices show, the first has the focus; when Next shows, Next has it; a button's own Enter and Space
press it, the Up and Down arrows move among the buttons, and the digits 1 to 4 pick a choice. Skip never takes the
focus by itself, and Space never skips: Space is most games' jump, and a player still tapping it when a cutscene
starts would skip it unseen. Enter skips, and so does a tap on Skip. Keys the box does not use are left alone, so
the game's own controls still hear them. A press reports once
through `on` and the box waits for its next `show`, so a double tap is one press. Held, or watching, the buttons do
nothing (watching, they are not shown). Its look comes from seven CSS properties, each with a default, set as
`touch.ts` sets the touch buttons': `--automata-story-background` (default `rgba(20,20,30,0.88)`), `-color`
(`#fff`), `-border`, `-radius`, `-font` (never under 18 px), `-button-background`, `-button-color`.
